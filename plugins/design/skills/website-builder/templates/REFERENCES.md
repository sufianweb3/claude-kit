# REFERENCES - the approved visual direction

Written at the design phase (`website-builder` 4b), **approved by the human before any UI code**,
then built against. Every UI section names the reference it executes.

**Status:** ⬜ draft - awaiting approval / ✅ approved YYYY-MM-DD

---

## How to fill this in

One to three references per category. Each needs a **link or a saved image**, and a one-line note on **what
specifically to take from it**. That note is the whole point - "nice hero" is not a direction, "hero stays on
one subject and lets the type breathe, no competing overlay" is.

Save screenshots and generated comps in `docs/design/references/` so the board survives without a network.

> **Reference, never replicate.** Take the principle, never the execution. Do not clone a competitor's layout,
> copy their assets, or lift their copy - it is a legal problem and a strategic one, because a site that looks
> like a competitor's cannot be preferred to it. If a reference can only be described by copying it, it is the
> wrong reference.

**Sources, in rough order of usefulness:** the user's own liked sites and competitors (ask first) · real sites
opened and screenshotted with the `playwright` MCP (evidence - someone shipped it) · live demos from
`ui-mate` and `ui-standards/references/libraries.md` (a reference you can install beats one you must rebuild) · generated comps from `taste-skill`
(`imagegen-frontend-web`, `brandkit`) - these are **concepts, not evidence**, so prefer real sites where they
disagree · `animation-vocabulary` to name a motion effect precisely instead of describing it vaguely.
